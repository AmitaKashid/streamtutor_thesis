# Browser echo and interruptions

Browser microphone capture and Web Audio playback share the same device. The microphone may pick up tutor speech from the speakers, and the existing VAD can mistake it for a person. The application already requested `echoCancellation: true`; it now requests browser AEC as an exact constraint and falls back to the previous preference if the browser reports that constraint cannot be met. The browser's reported setting is logged as `[MIC AEC]`; `true` means the setting was selected, not that echo was eliminated. If the browser reports `false`, the UI warns that AEC was not enabled. Speech is still captured while the tutor plays so genuine interruptions remain possible. No new buffering, network call, or speech-recognition pass was added to each audio frame.

This is a browser AEC request, not a new echo canceller. Browser, device, output route, microphone placement, room, gain, double-talk and speaker level can all affect it. There is no guarantee of zero leakage or zero added latency. Chromium's system-wide `echoCancellation: "all"` path can use an internally delayed loopback reference; it is not enabled by this change because its latency was not measured on the target device. A WebRTC loopback can make playback available as a WebRTC reference on some browsers, but changes the audio route and can add buffering and disturb audio/text synchronization; it is not enabled here either.

In a local experiment, a conservative time-domain reference matcher suppressed some synthetic echo but still left multiple possible false onsets on a speech sample with a simulated reflection. It was not shipped as an interruption gate. Real-device echo and double-talk testing is needed before deploying a stronger classifier.

## Acceptance test

Use the real browser, microphone and speakers with the same question and settings. Record the browser version, devices, capture AEC setting, output volume, and cold/warm state. Run at least ten responses for each condition: silence while tutor speaks at normal and high volumes, user interruption during speech, and no-speech noise during playback. Also test headphones and switching output devices. Count false interruptions per minute, real interruptions detected/missed, and time from user speech onset to interruption; measure end-to-end first-audio and word-synchronization timing as well. Compare before/after on the same hardware, and save no microphone recordings by default. A detected `echoCancellation: true` is not a measurement of echo reduction.
